# Legacy Business Rules and Edge Cases

## Student ID Generation
- Not automatically generated by backend; user manually inputs it (Format expected by UI placeholder: `202X-XXXXX-BN-X`).

## Duplicate Handling
- System blocks registration if `student_number` already exists in DB.

## Required vs Optional Fields
- Almost all fields are required except `middle_name`, `photo`, and `barcode_filename`.

## Derived/Computed Fields
- `FNMI` (First Name + Middle Initial) is computed dynamically during CSV export.
- `emergency_address` can be auto-filled by client-side JS if user checks "Same as Residential Address".
- `full_course_name` is injected dynamically on the backend during ID generation.

## Hardcoded/Implicit Values
- Academic year defaults to `AY 25-26` in model and seed scripts.

## Legacy-only / Unused
- `ChangeRequest` table exists in schema but is noted as "not yet enforced, for future use".
